Git integration for bemtvi. Its features compare against one diff base you
choose.

`:GitChanges` opens a picker of every changed file: staged, unstaged, deleted
and renamed files first, then untracked files, newest first, so the file you
just created is the first untracked row. In every buffer, added, changed and
removed lines are marked in the gutter and with a line background, as you type.

The diff base is `HEAD` unless you say otherwise, and it is a workspace option:
a workspace for a branch under review can compare against `origin/main` while
every other session keeps `HEAD`.

1. Commands                                              *bemtvi-git-commands*

>
    :GitChanges    Pick a file changed against the diff base.
<

Each row leads with the two porcelain status letters (`git status --short`
spells them the same way), coloured by the kind of change, then the
repo-relative path:

>
     M src/app.rs            modified in the worktree
    M  src/lib.rs            staged (or committed, against a base other than HEAD)
    A  src/new.rs            added
     D old.rs                deleted: listed, but there is nothing to open
    R  src/main.rs ← app.rs  renamed
    UU src/merge.rs          a merge conflict, in git's letters (UU, AA, DD, AU, ...)
    ?? notes/todo.md         untracked
<

A file you stopped tracking with `git rm --cached` is two rows, as in `git
status`: the staged deletion (`D`) and the file still on disk (`??`). Either
one opens it.

Untracked files are listed one by one, never as their directory, and stay below
every tracked change even while you filter. The one exception is an untracked
repository inside this one, which git does not walk into: it is one row spelled
with a trailing slash (`?? vendor/lib/`), and `<CR>` opens its directory
listing. The preview pane shows the highlighted file; `<CR>` opens it in the
main editor area (`<C-t>` / `<C-x>` / `<C-v>` in a tab or split, as in every
picker). The picker lists the repository that contains the editor's working
directory (`:pwd`).

2. Change marks                                      *bemtvi-git-change-marks*

Every file buffer in a repository shows how it differs from the diff base, line
by line:

>
    ▎  an added line      green sign, green line background
    ▎  a changed line     blue sign, blue line background
    ‾  removed lines      red sign on the line below the removal (a removal at the
                          end of the file marks the line above it with _)
<

The marks follow the buffer as you type: what is compared is the text in the
buffer, unsaved edits included, against the file at the diff base. They refresh
when you read, enter, show, edit or write a buffer, and the buffers on screen
refresh when the editor gets the focus back, so a commit or checkout made in
another terminal shows up when you return (a hidden buffer catches up when you
show it again). A commit made from bemtvi's own `:terminal` does not move the
focus; the marks catch up on the next edit, write or buffer switch.

A file that is not in the base (a new or untracked file) is all added lines. A
git-ignored file (build output, a local `.env`) gets no marks, nor do a buffer
with no file, a special buffer, and a file outside any repository. A file in an
encoding other than UTF-8 gets none either, and the plugin says so once: its
text in the editor and its bytes at the base would not compare. The same goes
for a file with old Mac line endings (`'fileformat'` is `mac`): git splits
lines on LF only, so to git the whole file is one line, and its changes would
not land on the editor's rows.

Turn either half off with an option:

>lua
    btv.o["git.change_signs"] = false   -- no gutter signs
    btv.o["git.change_lines"] = false   -- no line backgrounds
<

3. Diff base                                            *bemtvi-git-diff-base*

Two options decide what "changed" means, for the picker and the change marks
alike:

>
    git.base         the revision to compare against           default "HEAD"
    git.merge_base   compare against the merge base of          default false
                            git.base and HEAD instead
<

Set them like any option, for every session or for one workspace:

>lua
    btv.o["git.base"] = "main"                -- everywhere
    btv.wso["git.base"] = "origin/main"       -- this workspace only, saved with it
    btv.wso["git.merge_base"] = true
<

Against a base other than `HEAD`, a file you committed on your branch counts as
changed, as do staged and worktree edits. With `merge_base`, the base is where
your branch forked from `git.base` (what `git diff origin/main...` compares
against), so commits that landed on `origin/main` after you branched do not
show up as changes of yours. A base that does not resolve is reported by name.

4. Configuration                                    *bemtvi-git-configuration*

The plugin sets itself up when it loads, unless your config has already called
`setup()`. Call `setup()` to change the options' defaults, from your
`init.lua` or a `btv.plugins` `config`:

>lua
    require("bemtvi-git").setup({
      base = "HEAD",          -- default for git.base
      merge_base = false,     -- default for git.merge_base
      change_signs = true,    -- default for git.change_signs
      change_lines = true,    -- default for git.change_lines
    })
<

A value set with `btv.o` or `btv.wso` wins over these defaults. An unknown or
mistyped key is an error.

Loaded lazily (a `btv.plugins` spec with `cmd = "GitChanges"`, say), the plugin
marks the buffers already on screen as soon as it loads; the others get their
marks when you show them.

5. Highlights                                          *bemtvi-git-highlights*

Every group defaults to a colour of the active theme and yields to a
colorscheme or a user definition:

>
    GitChangesAdded       picker row of an added file
    GitChangesModified    picker row of a modified file
    GitChangesDeleted     picker row of a deleted file
    GitChangesRenamed     picker row of a renamed file
    GitChangesConflict    picker row of a conflicted file
    GitChangesUntracked   picker row of an untracked file
    GitChangesAddSign     gutter sign of an added line
    GitChangesChangeSign  gutter sign of a changed line
    GitChangesDeleteSign  gutter sign of removed lines
    GitChangesAddLine     line background of an added line
    GitChangesChangeLine  line background of a changed line
<

The line backgrounds are each accent faded into the theme's background, so
text stays legible.

6. Lua API                                                *bemtvi-git-lua-api*

>lua
    local gc = require("bemtvi-git")
    gc.pick(opts)     -- open the picker; opts are btv.picker.open overrides
    gc.list(dir)      -- promise of { root, files }: the rows the picker shows
<

Each file in `list()` is `{ rel, path, index, worktree, orig, kind, mtime, dir
}`: `path` is absolute and `nil` for a file gone from the worktree, `kind` is
one of `added`, `modified`, `deleted`, `renamed`, `conflict` or `untracked`,
`mtime` is set on untracked files, and `dir` is `true` on an untracked nested
repository. The picker source is registered as `git_changed`, so
`btv.picker.open("git_changed")` works too.
